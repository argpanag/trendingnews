AnyPS5 Achieves Full PS5 GPU Shader Instruction Translation

TheTools · 12.10.2026 00:18 · source · permalink

Friday, October 9th 2026 AnyPS5 Achieves Full PS5 GPU Shader Instruction Translation A few weeks ago, we reported on an intriguing project called AnyPS5, which aims to bypass emulation entirely and run PlayStation 5 games natively on Windows and Linux. Today, the project reached a significant milestone by successfully translating 100% of the PlayStation 5 GPU shader instructions. This achievement means that the "Oberon" graphics processing engine within the PS5 has been fully decoded. All 1166 GPU shader instructions, based on the RDNA 2 GPU IP, are now covered under the AnyPS5 project. The project relinks PS5 executables into the host system's native format and reimplements the console's system libraries for dynamic linking, similar to Wine or Proton. Since the PS5 already runs on x86-64 Zen 2 hardware, which is similar to a modern PC, AnyPS5 skips CPU emulation and recompiles shaders into SPIR-V for Vulkan instead. What is particularly interesting is that once GPU shader instructions are translated, all the system needs are PS5 libraries so they can be dynamically linked from a native PC port. This means the PS5 game will see the exact same system calls on a PC as it does on the console. However, the system libraries have not yet been fully translated, with current statistics showing 84.81% of system libraries translated. There are exactly 3034 system libraries native to the PS5, and currently, 2573 have been translated. Once the remaining 461 libraries are translated, we can expect PS5 games to run natively on PCs, bypassing emulation layers entirely. As a reminder, the PlayStation 5 GPU, codenamed "Oberon," features 2,304 shader units, 144 TMUs, and 64 ROPs, running with 16 GB of GDDR6 memory on a 256-bit memory bandwidth. Built on the 7 nm process and based on the Oberon graphics processor in its CXD90044GB variant, the device does not use DirectX; instead, console games are built against the platform's own graphics API.
