Claude Opus 5.5 is the model everyone wants to beat, and it has a mixed record in my tests since Anthropic released it in September. It beat Alibaba’s Qwen4-Max by being more accurate and three times faster. It beat Anthropic’s Fable 5.2 by matching its scores at about a quarter of the cost. It lost to OpenAI’s GPT-6.1 Terra, which was cheaper and faster across three tests.

OpenAI’s newest challenger, GPT-6.2 Sol, released on November 17th, claims to beat Opus 5.5 on both price and accuracy. For Sol’s accuracy claim, OpenAI’s launch post never mentions Opus 5.5 by name, but its charts do. They show Sol scoring slightly above Opus 5.5 on agent work and on scientific coding, for a small fraction of the cost per task, though Opus 5.5 stays slightly ahead on FrontierCode 2.0.

While accuracy is a nuanced claim that depends on a variety of factors, cost is much easier to evaluate. Sol costs $2 per million input tokens and $10 per million output tokens, which is half of Opus 5.5’s $4 and $20. OpenAI’s charts show Sol finishing agent tasks for about $1.30 each, compared with about $17 for Opus 5.5. Opus 5.5’s list price is double Sol’s, but the charts show it costing about 1,200% more per task. That means Sol must use far fewer tokens than Opus 5.5 to do the same work.

To find out whether Sol really beats Opus 5.5, I ran both on the same agent, coding, and data analysis jobs. I compared them on accuracy, tokens, cost, and speed.

These are the same three tests I used for GPT-6.2 Astra and Fable 5.2. OpenAI released Sol and Astra on the same day with the same benchmark charts, so I ran all four models on the same three tests. That also lets you compare the results across both stories.

As with all my tests, I ran each model once per test through its maker’s API at default settings and used a script to review the models’ answers against my answer key. Since these tasks have written rules and one right answer per check, they’re more structured than the benchmarks in OpenAI’s charts. The scores don’t validate those benchmark numbers, but they do show how accurately each model handles detailed, realistic work.

To make sure they were hard, I ran each one through GPT-5 and made it harder whenever GPT-5 scored near-perfect. GPT-5’s scores on the hardest versions are below for reference.

This was the agent test, where OpenAI’s charts show Sol slightly ahead. In my test, Opus 5.5 was ahead. It scored a perfect 173/173, and Sol scored 169.

Sol’s four missed points trace back to one customer. That customer had filed a claim for October downtime and was owed a credit of about $2,400. Sol never issued it, which also made the totals in its close report wrong. Everything else Sol did matched Opus 5.5, including every mispriced invoice and every request it had to refuse. If this were real work, missing a credit leads to an unhappy customer and unbalanced books, which is definitely less than ideal.

The numbers:

Both models scored a perfect 110 out of 110. Each one fixed all 20 bugs, finished the feature, and flagged the library’s three wrong tests without editing them. Sol even caught the one rule that tripped up its bigger sibling, GPT-6.2 Astra, on this same test.

“For coding work like this, Opus 5.5’s extra reasoning didn’t find anything that Sol missed.”

With identical scores, the difference is the bill. Opus 5.5 cost 97 cents and took three and a half minutes. Sol cost 16 cents and took a minute and a half. For coding work like this, Opus 5.5’s extra reasoning didn’t find anything that Sol missed.

This is the closest thing in my tests to the scientific coding in OpenAI’s charts, where Sol is shown ahead. Here, the two tied, both scoring 76 out of 76. 

This was also the closest test on cost and time. Opus 5.5 cost 58 cents to Sol’s 15 cents and took about 50% longer. Opus 5.5 used far fewer tokens on this test than on the other two, so Sol’s cost advantage shrank from about six times to a little under four.

The numbers:

Sol didn’t beat Opus 5.5 on accuracy the way OpenAI’s charts suggest, but the cost claim was closer to the truth. The choice comes down to a little more accuracy or a lot less money.

I’d start with Sol. It tied Opus 5.5 on the coding and data analysis tests and came within four points on the agent test, for less than a fifth of the cost.

“Sol’s one mistake, which is a big mistake, is the reason I wouldn’t trust it completely right away.”

Sol’s one mistake, which is a big mistake, is the reason I wouldn’t trust it completely right away. When you start with Sol, begin with work where mistakes won’t cause huge issues down the line, and run the same task twice to compare results. For work where a mistake causes huge downstream issues, I’d keep Opus 5.5 as the final check.
