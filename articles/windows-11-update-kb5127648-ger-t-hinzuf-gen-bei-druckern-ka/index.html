Windows 11 Update KB5127648: „Gerät hinzufügen“ bei Druckern kaputt?

TheTools · 23.10.2026 22:08 · source · permalink

Das kumulative Update KB5127648 für Windows 11 24H2 – 26H2 vom 13. Oktober 2026 scheint einen weiteren Kollateralschaden hervorzurufen. An Servern freigegebene Drucker lassen sich nicht mehr über "Gerät hinzufügen" einrichten. Es gibt neben Hinweisen hier im Blog weitere Berichte zu diesem Problem. Und es gibt einen Workaround, um das Problem temporär zu lösen.

Windows 11 Update KB5127648

Microsoft hat zum Oktober 2026-Patchday das kumulative Update KB5127648 für Windows 11 24H2-26H2 veröffentlicht. Ich habe im Blog-Beitrag Patchday: Windows 10/11 Updates (13. Oktober 2026) über die durch das Update ausgerollten Fixes und Verbesserungen berichtet. In der Liste der Fixes heißt es, dass Microsoft ein Problem mit Druckern von August 2026 behoben habe.

Leserhinweis auf Druckerproblem

Zum 15. Oktober 2026 hat sich Blog-Leser Andreas mit diesem Kommentar gemeldet. Er beklagt Probleme nach dem Update KB5127648 beim Hinzufügen von unter Windows Server freigegebenen Druckern am Windows 11-Client.

  • Der freigegebene Drucker lasse sich am Windows 11-Client nicht mehr über den Schalter "Gerät hinzufügen" der Einstellungen-Seite installieren (siehe auch diese Microsoft-Beschreibung).
  • Der freigegebene Drucker lässt sich nur noch über die Option "Fügen Sie ein neues Gerät manuell hinzu" auf dem Windows 11-Client installieren.

Laut Leser ist es dann aber egal, ob man über das Verzeichnis oder den Freigabepfad geht. Dann hat der Leser das kumulative Update KB5127648 testweise deinstalliert. Danach funktioniert es wieder, einen Drucker über den "Gerät hinzufügen"-Schalter am Client einzurichten. Ein weiterer Leser bestätigt in diesem Kommentar das Problem.

Bericht auf patchmanagement.org

Parallel ist mir der Thread October's CU Throwing Error 87 When Adding a Printer vom 22. Oktober 2026 auf patchmanagement.org untergekommen. Dort schreibt ein Betroffener, dass nach dem Oktober 2026-Update KB5127648 unter Windows 11 25H2 Probleme auftreten.

Hello all,
After updating to this month's Windows 11 25H2 CU we are having issues where users on our AD network attempt to add a shared printer to their machine via Settings → Bluetooth & devices → Printers & scanners → Add device and are presented with Error: #87. However, if you scroll down and manually add a printer via a directory search the printer will install without issue.
Rolling back October's CU fixes the issue. Is anyone else seeing this issue?

Die Zusammenfassung der obigen Beobachtungen lautet:

  • Benutzer im AD-Netzwerk, die versuchen, über Einstellungen – Bluetooth und Geräte -Drucker und Scanner – Gerät hinzufügen einen freigegebenen Drucker zu ihrem Computer hinzuzufügen, erhalten die obige Fehlermeldung: #87.
  • Scrollt der Benutzer in der Einstellungen-Seite jedoch nach unten und fügt den Drucker manuell über eine Verzeichnissuche hinzu, lässt sich der Drucker problemlos installieren.

Ein Rollback des kumulativen Updates KB5127648 von Oktober 2026 behebt das Problem. Der Nutzer fragt: "Tritt dieses Problem noch bei jemand anderem auf?".

NTLMv1-Blockierung als Ursache

Ich hatte im Blog-Beitrag Windows 11 24H2 / Server 2025: Erinnerung an bevorstehende Änderungen an NTLMv1 vor dem Oktober 2026-Patchday daran erinnert, dass Microsoft aus Sicherheitserwägungen Änderungen an NTLMv1 vornehmen werde. Das NTLMv1-Protokoll wurde bereits aus Windows 11, Version 24H2, sowie aus Windows Server 2025 und späteren Versionen entfernt (Removed features and functionality).

Obwohl das NTLMv1-Protokoll entfernt wurde, sind in einigen Szenarien jedoch noch Reste der NTLMv1-Kryptografie vorhanden, beispielsweise bei der Verwendung von MS-CHAPv2 in einer domänengebundenen Umgebung, schreibt Microsoft.

Mit dem Sicherheitsupdate KB5127648 vom Oktober 2026 hat Microsoft den Standardwert des Registrierungsschlüssels BlockNTLMv1SSO von bisher 0 (Audit-Mode zum Überwachen) auf 1 (Enforce) umgestellt und dadurch NTLMv1SSO deaktiviert. Das betrifft Windows 11 24H2 und höher sowie Windows Server 2026.

Es gibt einen Workaround: NTNLv1 zulassen

Andy bestätigt in diesem Kommentar die oben erwähnte Verschärfung der Sicherheitsstufe für die NTLMv1-Authentifizierung als Ursache für das Problem. Diese Verschärfung wurde von Microsoft mit dem Update KB5127648 vorgenommen. Die Einstellung BlockNtlmv1SSO steht nun auf "Enforce"/Blockieren.
